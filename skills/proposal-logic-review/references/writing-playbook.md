# 写作手册：从说明“做什么”到论证“为什么这样做”

## 1. 本篇形成的风格

这是研究计划，不是领域综述、项目广告或实现手册。保留专业术语，但每个抽象词必须落到对象、变量或决策；每个段落只推进一个主要判断。表达清楚不等于删掉边界，表达谨慎也不等于用大量免责声明包围论点。

当前确认稿的特征：

- 背景从城市数字孪生的成果要求出发，随后引出规模化构建为什么需要考虑成本，最后落到已有配准数据下的研究目标。
- 3DGS 在现状入口被介绍为可行路线，而不是在背景里宣布它不可替代。
- 研究现状按“规模、几何与质量、训练成本”三类组织；这些维度彼此相关，但不默认所有论文共用某一计算流程。
- Gap 综合三类进展，指出仍需建立随表面和观测条件变化的配置依据，不靠单篇论文例子包办领域局限。
- 两项科学问题采用“学术概括＋直接问句”，最后说明两问的依赖关系。
- 方法开头先讲各方法之间的依赖；正文交代目的、主要操作、产出与检验，不铺开所有参数与失败分支。
- 验证要点在方法和访问安排中出现；当前确认稿不设独立的“成功判据”小节。
- 成果、资源、原型演示分开。机器人、前馈高斯与自动驾驶属于潜在用途，不替代主要研究目标。

## 2. 两页中的内容分配

这是本案例的默认版式，而非所有资助项目的统一规定。外部申请要求优先。

### 第一页：让读者知道问题为什么成立

**背景与目标：**应用需要什么成果 → 为什么质量与计算成本都重要 → 具体输入与目标。这里不放相机分辨率、法向估计、损失函数或提前排除 SLAM 的说明。

**现状与问题分析：**介绍研究技术与目标的关联 → 按相关能力分类承认已有进展 → 综合指出仍需什么判断依据。分类不是单纯编目，最后必须服务于同一个问题。

**关键科学问题：**提出一至数个有关系的问题，数量由课题决定。本案例两问分别对应“必要配置是什么”和“怎样以更低成本实现配置”。末句给出共同质量与成本口径。

### 第二页：让读者知道方法为何能检验问题

**方法间关系：**先说明第一项产生什么，第二项如何使用，第三项再解决什么。不要只写“包括三个模块”。

**每项方法：**目的／必要性 → 主要操作 → 可观察结果 → 关键对照或下游用途。

**访问安排与预期成果：**计划和已有基础分开；资源与时间可行；预期结论与潜在应用分开。当前案例中真实验证并入此处和方法段，不恢复被用户删除的独立章节。

**参考文献：**独立编号和页数规则，按提交要求执行；编号占位必须在正式交付前解析为真实来源或明确标记未核实稿。

## 3. 每一段到下一段的桥

| 连接 | 要表达的关系 | 本案例的推导方式 |
|---|---|---|
| 背景 → 目标 | 预期用途为什么要求这种成果？ | 空间量测与实景呈现要求兼顾几何和外观；大范围使用要求成本可承担。 |
| 目标 → 技术 | 为什么研究该路线，而非只因熟悉？ | 显式局部表示与新视角输出使其成为合适研究对象，不声称唯一。 |
| 技术 → 现状 | 社区已经使哪些能力成为可能？ | 大规模组织、几何引导表示、成本与训练加速。 |
| 现状 → Gap | 已有成果仍不足以决定什么？ | 有效配置已经存在，但给定新观测时如何判断何种配置足够，仍是研究目标。 |
| Gap → 问题 | 为何需要研究某种关系？ | 信息不足与表示不适配需要不同干预，不能只按数量或残差统一处理。 |
| 问题 → 方法 | 为什么这些操作能提供判别证据？ | 独立控制观测与表示，再检验依据这些关系配置是否减少总成本。 |
| 方法 → 成果 | 哪种结果才兑现开头的目标？ | 新场景中保持质量并减少总处理成本，才支持可规模化构建的价值。 |

“因此、然而、进一步”只提示关系，不创造关系。删除这些词后，前提仍应支持结论。若只能靠常识补全，要判断该常识是否稳固，或将桥标为待检验假设。

## 4. 段落句型

### 背景

> [应用]需要具备[关键质量]的[成果]，用于[明确用途]。当[部署范围／频率／规模]扩大时，达到该质量所需的[代价]也成为目标的一部分。因此，本研究利用[已有输入]，研究在[质量与资源边界]下如何改善[明确终点]。

不要把所有项目都写成资源受限；这是该案例的目标。如果实际问题是鲁棒性或解释性，第二句与成功指标必须一起改变。

### 相关工作

> [方法类别]针对[子问题]采用[核心做法]，已有证据支持[具体进展]。

无需在每篇后面强接一句“但它没有做我的方法”。先用共同问题组织，再综合讨论尚缺依据的决策。

### Gap

> 现有研究已在[相关方面]取得进展，但面对[特定条件变化]，仍需判断[具体配置／预测／推断]。本研究拟检验[候选关系或判断依据]是否能在[目标终点]上带来额外价值。

“仍需”是研究定位，不是凭语气变成文献穷尽证明。对已有人直接研究的部分要承认交集；无法证实空白时缩小主张。

### 科学问题

> **[专业关系名称]：[直接问句]？**研究[条件]下[变量]如何影响[响应]，识别[状态／适用条件]，为[决策]提供依据。

### 方法

> 为回答[问题]，拟通过[操作]使[因素／机制]可区分；得到[结果]后形成[可执行产出]，并用[对照]检验其是否产生[与目标一致的收益]。

### 预期成果

> 预期形成[可交付对象]与[适用条件]；若在[独立验证]中满足[判据]，将为[应用]提供[有限且具体的价值]。

正式稿不必机械使用所有占位句式；保留功能即可。

## 5. 压缩而不削弱论证

优先删除三类内容：重复的价值宣言、在现状和科学问题中反复出现的同一句话、无关核心问题的工具和实现列表。

不能优先删除：问题与方法的连接句、关键输入差异、总成本口径、假设身份、独立验证条件。

适合合并的例子：

- 冗余：“减少耗时和资源开销，以更低成本进行规模化构建，从而高效建设大规模场景。”
- 可替换：“在保持质量的同时，降低大范围场景的构建成本。”

需要解释的名词：

- “容量”究竟包含数量、形状、分布还是可优化参数；
- “有效”相对于什么已有信息和目标；
- “高质量”以什么独立对象评价；
- “机制”是什么条件关系，怎样与替代解释区分。

不要用“全链路闭环协同赋能”替代以上定义。正文中如需表达整个流程的耗时，优先“总处理与训练时间”，避免让“端到端”同时承担成本口径和模型类型两种含义。

## 6. 同一信息在三个载体中的粒度

| 内容 | 正式两页正文 | 审查记录 | 技术执行计划 |
|---|---|---|---|
| 因素控制 | 哪些关键因素独立变化、为何 | 哪些变量混杂、如何否定 | 组号、采样范围、种子和提交版本 |
| 损失与优化 | 作用对象、阶段依据、目标 | 是否对应主张、替代解释 | 公式、权重、梯度与代码路径 |
| 真实性 | 合成真值的适用对象 | 泄漏和同源参考风险 | GT来源、哈希、数据划分 |
| 效率 | 总成本与质量保持 | 是否漏算开销、对照公平性 | profiler、硬件、累计更新统计 |
| 风险 | 影响结论的必要限定 | 完整失败条件和改法 | 回退、验收阈值、停止条件 |

删掉审查式长说明不等于删除验证要求；应把要求放在最能承接结论的位置。

## 7. 中文—英文与版本控制

同一段落的目标、输入、条件、状态、方法产出与参考文献编号应一一对应。中文的“拟研究、有望、初步探索”不能译成“demonstrates, guarantees, achieves”；英文不能为压缩而删掉“at comparable quality”等关键约束。

不要机械逐词翻译“机制、表征、底座”。可使用符合上下文的 mechanism/relationship、representation、spatial foundation，但术语表必须稳定。

局部确认的修改单独记录：指定底稿、修改范围、保留段落、已删除内容、是否重编号。若发现其他问题，提出旁注，不擅自全篇改写。

版式应先压縮内容，再调整段落间距，最后再考虑字号。不得通过不可读的小字体兑现两页要求。正文和参考文献使用明确分页；分别渲染中英文 PDF 检查页数、溢出和链接。
